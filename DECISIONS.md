# DECISIONS.md — conservative choices for ambiguities

Log genuine ambiguities here instead of blocking. Newest first.

## 2026-09-22 — Supabase DB hosting: session pooler, no schema change (agent)
- **Single-service deploy shape (internet URL + desktop app):** all API routes now live under `/api` (one `prefix` per plugin in `index.ts`; dev proxy forwards untouched so dev/prod share one URL shape), and `SERVE_WEB=1` makes the API serve `apps/web/dist` with an SPA fallback (`/api/*` still 404s JSON). The web client takes its origin from build-time `VITE_API_URL` (empty = same-origin). Lesson: `@fastify/static` must keep its default `wildcard` — with `wildcard:false`, misses 404 directly and never reach the custom not-found handler. Verified live: `/`+asset+`/billing` → 200, `/api/auth/me` → 401 JSON, login + dashboard work.
- **Cross-origin login (desktop/split hosting):** `SESSION_COOKIE_SAMESITE` (`lax` default; `none` implies `Secure`, enforced server-side since browsers reject None without it). Local dev stays lax over http; the hosted API uses `none`.
- **`pnpm dev` degrades like `pnpm -r build` now:** root `dev` fans out to every package, and `apps/desktop dev` was bare `tauri dev` (needs Rust) while `apps/mobile dev` was bare `vite` (no entry file) — either one killed the whole parallel run on a plain dev box. Both are now `node scripts/dev.mjs` wrappers that skip with an explanation and exit 0 when their toolchain/entry is absent, and exec the real command otherwise. Verified: `pnpm dev` boots web :5173 + api :3001 (health ok) with desktop/mobile skipping loudly.
- **RLS enabled deny-by-default (user-applied SQL):** `ENABLE ROW LEVEL SECURITY` on every public table with no permissive policies. The API connects as `postgres` (superuser, bypasses RLS), so app behavior is unchanged; this only denies Supabase Data API roles (`anon`/`authenticated`) as defense-in-depth. Real tenant isolation stays in the API layer (`business_id` on every query + server-side RBAC). When/if login migrates to Supabase Auth, add tenant policies keyed on the JWT then — not before.
- **Declined `@supabase/server`:** it verifies Supabase Auth JWTs, but ecoBills uses hand-rolled session cookies + Prisma-to-Postgres, so it would be an unused dependency. Stored `SUPABASE_URL` + publishable key in local `.env` (placeholders in `.env.example`) as reserved for a future Auth/Storage move; secret left blank to fill from the dashboard. Migrating login to Supabase Auth is a separate, non-trivial task — do it only if managed auth becomes worth the rewrite.
- **Two variables, no migration of code:** moving to Supabase means pointing `DATABASE_URL` and `DIRECT_URL` at the dashboard's **session pooler** string (pooler host, port 5432) and adding `directUrl = env("DIRECT_URL")` to the schema (done — validation passes, no data migration involved). Session mode behaves like a direct connection, so `SELECT … FOR UPDATE` + interactive transactions (gapless invoice numbering) are unaffected, and it works on IPv4 networks where the direct `db.REF` host (IPv6) may not route. Verified against Supabase + Prisma docs (Sep 2026). Your project is in ap-south-1 (Mumbai) — good latency for India users.
- **Transaction pooler (6543 + `?pgbouncer=true`) is forbidden for this app** — interactive transactions are unsupported in transaction mode, which would silently break the invoice-counter atomicity (§1 non-negotiable). Documented in `.env.example` and README.
- **Backups get more important, not less:** automatic daily backups are Pro+ only; free tier has none and pauses after a week idle. The `pg_dump` job works unchanged against Supabase (it just needs the connection string) — keep it scheduled, and require Pro before GA.

## 2026-09-22 — root .env is now honored by every command (agent)
- **Problem:** `pnpm --filter` runs each package with its own dir as cwd, so a repo-root `.env` was invisible: `db:migrate` (cwd `prisma/`) failed with P1012 "env var not found", and `db:seed` / `pnpm dev` (cwd `services/api/`, dotenv loads cwd `.env`) would have done the same even with a root `.env` present.
- **Fix:** `services/api/src/env.ts` loads the root `.env` by explicit path (shell env still wins) and is imported first by `index.ts` and `seed.ts`; `prisma/scripts/with-env.mjs` preloads the root `.env` via `process.loadEnvFile` (Node ≥20.12) before exec'ing prisma, and the `migrate:*`/`generate` scripts route through it. Verified: both commands now get past validation and fail only with P1001 "can't reach server" when no Postgres is running. No new dependency.
- **Still needed on a fresh machine:** a real database (Docker Desktop, local Postgres, or hosted) + `pnpm db:migrate && pnpm db:seed`.

## 2026-09-22 — fluid-UI redesign: motion system + component reskin (agent)
- **Presentational and interactional change only.** No route was added, removed or re-pathed; no API endpoint, payload or status code changed; RBAC is untouched (`isOwner` checks in Billing/Orders/Reports still gate exactly what they gated before); and money/stock derivation is byte-for-byte the same — paise stay `Int`, tax rates stay basis points, qty stays `Decimal(12,3)`, and `formatMoney` still converts only at render time. Every screen's data hooks (`useQuery`/`useMutation` keys, `invalidateQueries` calls, mutations) are unchanged. The diff is tokens, CSS, component internals and JSX presentation.
- **Active Theory / preset-06 adapted, deliberately restrained.** The aesthetic direction is preset 06, and the honest read of it is a *pointer-reactive ambient surface with depth* — so that is the one idea borrowed, in `packages/ui/src/ambient-field.tsx`: three soft radial glows plus two counter-moving dot lattices at different travel depths. It is restrained because spec §7 forbids cinematic reveals, parallax and scroll-hijacking. Concretely: **no scroll listener at all** (the field is `position: fixed`, outside every scrolling container), **no React state** (pointer position goes into MotionValues and is coalesced to one write per frame, so moving the pointer re-renders nothing), **no timer** (an idle screen does zero work — this is the deliberate deviation from preset-06's "always drifting" surface, which would repaint forever), and **transform/opacity only** (the glows are pre-softened gradients rather than `filter: blur()` elements, so a move composites rather than repaints). It is `aria-hidden` and `pointer-events-none` decoration, and it never competes with the one eye-drawing element §7 allows.
- **The motion tokens are the single source of truth.** `packages/ui/src/motion-tokens.ts` defines every duration, easing and spring once, and nothing else in the repo may declare one. It is mirrored (not duplicated) into `packages/config/tokens.css` as custom properties, into `packages/config/tailwind.preset.js` for the `duration-*`/`ease-*` utilities, and re-exported to app code through `apps/web/src/lib/motion.ts`. `packages/ui` owns the numbers because the workspace dependency only points one way (web → ui). Continuous motion (spinner rotation, shimmer sweep) is defined separately as `indeterminate` because an endless loop has no entrance duration and must be linear. `MOTION.md` is the handoff spec.
- **Brand green taken from the mtrx.labs logo.** `--color-brand: #1e8906` is the real logo green, and `--color-action` uses it so white button labels hit 4.53:1 (AA for 14px). The ecoBills accent `#17a673` is kept for identity wherever it is not carrying text (`--color-accent`, tints, borders, charts), with `--color-accent-text: #0f6e4b` as the 6.26:1 token for accent-as-text. Dark mode flips to `--color-accent-text: #85e46b` (11.2:1). Focus rings are >=3:1 in both modes and always offset, so the ring is measured against the page background rather than the control's own fill.
- **Reduced motion is a contract, not a nice-to-have.** Transform-based motion is stripped (translate, scale, rotate, `pathLength`, shared-layout), while opacity and colour crossfades are deliberately **kept** — a blanket `* { animation: none; transition: none }` reset would flatten every hover and focus response and make the interface feel broken. All function survives. Enforced twice: `<MotionConfig reducedMotion="user">` in `apps/web/src/App.tsx` as a global net, plus explicit per-component gating through the token-aware builders. The app owns its own `useReducedMotion()` instead of Framer Motion's because v11 reads the media query once and never updates; ours is reactive, so flipping the OS setting applies without a reload.
- **Screens gained the states they were missing:** every screen now has a designed Empty state, a `Skeleton*` loading shape that mirrors its real layout (never a generic spinner, per §7), and an Error state with a recovery action (`refetch`). The two success celebrations (bill created, PO sent) now share one hold duration (`motionLimits.successHoldMs = 1400`) instead of the previous mismatched 1600/1400ms literals.
- **No new npm dependency was added by this redesign.** It is built on the `framer-motion` and `recharts` already listed in `apps/web/package.json`, plus hand-written inline SVG icons — emoji used as interface icons were removed in favour of the shared 1.5px line set, so no icon package was needed.
- **Known gap (pre-existing, unchanged):** `apps/mobile` still has no Vite entry or React dependency, so the dashboard-only bundle is produced by `@ecobills/web build:dashboard` (`VITE_DASHBOARD_ONLY=true`). The route-level strip it depends on is intact and verified.

## 2026-09-22 — resilient recursive build + Tauri v2 config fix (agent)
- **Tauri v2 tray icon shape:** `app.trayIcon` takes a `TrayIconConfig` object that *requires* `iconPath` (string) and rejects unknown keys (`additionalProperties: false`). The old `{ "icon": ["icons/32x32.png"], "tooltip": "ecoBills" }` used the *bundle* `icon` array shape, which is why `pnpm -r build` died in config validation on every machine, Rust or not. Now `{ "iconPath": "icons/32x32.png", "tooltip": "ecoBills" }`. Verified against the CLI's bundled `config.schema.json` ($id `…/config/2.11.6`), identical to `https://schema.tauri.app/config/2`.
- **Desktop build degrades without Rust:** `apps/desktop` `build` is now `node scripts/build.mjs`. If `cargo`/`rustc` are absent it prints provisioning instructions and exits 0; otherwise it runs the real `tauri build` and propagates its exit code verbatim (compile/bundler failures still fail the build). `ECOBILLS_REQUIRE_DESKTOP=1` turns a missing toolchain into a hard failure — use it on release/packaging machines so a skip can never be mistaken for a packaged app. Reason: keep `pnpm -r build` green on web-only boxes (and CI image builders) without silently swallowing genuine errors.
- **Mobile build degrades the same way:** `apps/mobile` `build` is `node scripts/build.mjs`; it skips the Vite step while `apps/mobile/index.html` does not exist, and skips `cap sync` while no `android/`/`ios/` platform is initialised, each with a loud one-line explanation. `VITE_DASHBOARD_ONLY=true` is still applied to the Vite step and real vite/cap failures still fail the build. Known gap (phase 8, pre-existing): `apps/mobile` has no Vite entry and no React dependency yet, so the dashboard-only bundle is currently produced by `@ecobills/web build:dashboard`; add the entry + React when the mobile shell is fleshed out.
- **Desktop icons:** generated with the official `tauri icon` CLI from `apps/desktop/app-icon.png` (checked in as the source icon) into `apps/desktop/src-tauri/icons/`. `bundle.icon` now lists the standard set including `icons/icon.ico`, which Windows/NSIS packaging requires. No new npm dependency: the icon generator ships with `@tauri-apps/cli` and needs no Rust.
- **Rust scaffold completed:** `apps/desktop/src-tauri/` had only `tauri.conf.json`, so packaging could not work even with a full toolchain. Added the canonical Tauri v2 scaffold (`Cargo.toml`, `build.rs`, `src/main.rs`, `src/lib.rs`, `capabilities/default.json`, `.gitignore`) generated by `tauri init` and adapted (crate/lib name, version, description) — plus `tray-icon` and `image-png` features, both required by the tray config. NOT compile-verified in this env (no cargo/rustc); verify with `pnpm --filter @ecobills/desktop build` on a provisioned machine.
- **Deferred (pre-existing, not touched):** `tauri.conf.json` declares `updater`/`notification`/`autostart` plugins and `apps/desktop/src/native.ts` imports `@tauri-apps/plugin-notification`, but no `@tauri-apps/api`/plugin JS packages or plugin crates are installed. Config-only plugin entries are accepted by the CLI and harmless at build time; wire the crates+JS when the notification/updater features land.

## 2026-09-22 — initial scaffold (agent)
- **Auth:** hand-rolled scrypt sessions (httpOnly cookies) instead of Lucia/Clerk for v0.1, to keep zero external auth dependency and work fully offline in dev. Threat model documented in `services/api/src/auth.ts`. Swap to hosted auth later without changing RBAC middleware shape. Reason: conservative — easiest to change later, no vendor lock-in before GA.
- **No Docker in this build env:** `docker-compose.yml` ships for real dev machines; API boots and serves 503 on DB-dependent routes until `DATABASE_URL` connects, so `pnpm dev` still boots per Phase 0 DoD.
- **Prisma cuid:** uses `cuid()` (Prisma built-in) for all PKs per spec, not uuid.
- **Money:** all money Int (paise), tax rates Int basis points, qty Decimal(12,3) per spec §5 (weight/volume support).
- **Invoice numbering:** `InvoiceCounter(business_id, financial_year)` + `SELECT … FOR UPDATE` inside creation transaction. Financial year = India April–March (`FY2026` = Apr 2026–Mar 2027). Prefix configurable via `Business.invoice_prefix`.
- **PDF:** Puppeteer HTML-template render; API on Render/Railway/Fly (long-running container), web static on Vercel/Netlify/CF Pages — per v0.1.1 hosting fix. Share action = OS share sheet + WhatsApp deep link.
- **Email:** Resend if `RESEND_API_KEY` set, else logged stub (never throws in dev). Idempotency key generated at draft creation, sent as Resend `Idempotency-Key` header equivalent + DB guard.
- **AI polish:** optional endpoint `POST /purchase-orders/:id/polish` — proxies structured order to `LLM_POLISH_API_URL` if configured, else 501 with clear message. Never auto-sends.
- **Backups:** `pnpm backup` runs `pg_dump`; `BACKUP_CRON` schedule doc in Phase 9. Must run before GA, not Phase 0 (per v0.1.1 clarification).
- **Mobile dashboard:** `VITE_DASHBOARD_ONLY=true` build flag strips Billing/Reports-create routes at build time (route not shipped, not just hidden).
